# 全项目性能审查与优化

日期：2026-10-17。审查对象为工作区的 0.2.1 版本，包含已有但尚未提交的提示词、时间线、设置和快捷键功能。性能基线取自**本轮修改前的完整运行源码及构建/测试快照**，并非较旧的 Git HEAD。本轮保留原有改动，没有改写数据或自动提交这些新功能。

## 结论与优先级

主要问题出现在持续监听页面变化的辅助功能，而不是 PNG 拼接算法：时间线在流式输出时反复做全页索引、二次方消息匹配及隐藏列表重建；提示词关闭时仍建立完整 DOM；截图滚动函数与调用者重复等待同一稳定布局；PNG 字节转换还有可避免的迭代开销。全页样式扫描有成本，但不能用仅靠 DOM 观察失效的缓存替代。

| 优先级 | 问题与证据 | 频率 / 风险 | 实施结果 |
| --- | --- | --- | --- |
| P0 | 500 轮对话、12 次流式更新创建数万个临时元素，主线程任务达秒级 | 流式输出高频；中等适配风险 | 按回复增量更新、线性匹配、保持刻度节点、关闭列表不渲染；导航及检索回归通过 |
| P1 | 1000 条提示词在面板关闭时仍创建约 1.8 万个元素 | 初始化、跨标签数据更新；低风险 | 可见时才渲染；缓存行和搜索数据，关闭释放 |
| P1 | `/` 列表每次高亮更新写入全部候选属性 | 键盘与鼠标移动高频；低风险 | 只更新前后两个候选，合并同帧输入/选区刷新 |
| P1 | 滚动内部已验证稳定，调用者立即重复轮询同一布局 | 每个后续分片；有明确调用链与阶段计时 | 即时签名复核，处理 pending MutationRecord；未降低稳定阈值 |
| 保留 | 10 次截图 DOM 几何准备读取约 7 万次计算样式 | 随分片数增加；错误缓存风险高 | CSSOM 探针复现缓存漏检浮层，撤回候选缓存，保留完整检查 |
| P1 | PNG base64 用 `Uint8Array.from(string, callback)` 逐字节回调 | 每个分片及复制；低风险 | 直接分配字节数组和循环，复用预览 Blob |
| P2 | 提示词导入嵌套查重、构建未压缩、公式隐藏重复定时 | 显式操作或加载；低风险 | 集合查重、esbuild 压缩、隐藏定时合并 |

没有降低截图质量、减少正文或缩小单张上限，也没有改为后台重载 ChatGPT。稳定验证仍要求原有连续样本和变更后静默时间，只复用滚动刚返回的同一签名；没有跨任务缓存稳定状态。UI 模板、样式、动画时长、快捷键、排序规则、草稿插入和备份字段保持原样。

## 实际架构与生命周期

Manifest V3，最低 Chrome 118；TypeScript + 原生 DOM/Shadow DOM，esbuild 构建。运行时代码没有第三方依赖，KaTeX 只用于测试夹具。存在 Content Script、Service Worker、设置 Popup 和临时预览页；没有独立 Options Page。

| 模块 | 职责、数据与通信 | 常驻成本与清理 |
| --- | --- | --- |
| `content.ts`、`adapter.ts` | 单次安装标记；发现助手正文和操作区；协调截图、提示与忙碌状态 | body 的 childList/characterData Observer，150ms 合批并限定到变化轮次；按钮关联用 WeakMap |
| `capture.ts`、`page-state.ts`、`stitcher.ts` | 前台 CDP 滚动捕获；校验几何和正文修订；按真实像素拼接 | 仅任务期间观察、等待和分配；每帧 Bitmap 在 finally 关闭；结束/失败/取消释放画布、观察器并恢复页面 |
| `background.ts`、`transport.ts` | 鉴权、调试会话租约、JSON/base64 分块传输、临时预览缓冲 | 没有生产轮询或常驻保活；导航/关闭/外部 detach 清理；预览有容量和过期限制，不持久化图片 |
| `clipboard.ts`、`preview.ts` | PNG 剪贴板；预览、重试、保存 | Blob URL 在清除/pagehide 撤销；迟到结果受 generation 保护；复用一个 PNG Blob，编码字符串不再长期保留 |
| `prompts.ts`、`prompt-data.ts`、`prompt-orb.ts` | 管理、`/` 检索、原生编辑事务插入、备份、位置 | `storage.local` 的 `nativeLongshot.prompts.v1` 数组；变更跨标签同步；搜索不写存储；关闭清空列表/候选及缓存 |
| `timeline.ts`、`timeline-dom.ts`、`timeline-data.ts` | 从已加载问题与回复构建索引、搜索、定位和高亮 | 首次启用才初始化；180ms 合批；正文流式变更只重读对应回复；ResizeObserver 合并到一帧；关闭功能取消任务、断开观察、清空节点与消息引用 |
| `layout.ts` | 可选的助手回复扩宽 | 默认关闭；不再订阅 characterData；保留结构变化/resize 发现；截图忙碌时不改布局 |
| `thinking.ts`、`thinking-hotkey.ts` | Fn+左右/备用命令调用原生强度控件 | 平时只处理事件；轮询仅在用户触发、最多 1.8s；不写私有站点 API |
| `latex.ts` | 指针附近显示源码复制按钮 | 委托监听，不扫描公式全集；关闭/截图忙碌直接返回；隐藏定时最多一个 |
| `popup.ts`、`settings.ts` | 开关、宽度、时间线样式、导入导出 | 只在 Popup 打开时运行；设置保持按序保存并通知当前标签页 |

提示词数组仍包含 `id/name/content/tags/favorite/useCount/lastUsedAt`，更新保存完整数组，保留原存储顺序；显示排序仍为收藏、使用次数、最近使用时间、稳定的原次序。时间线只在内存保留已加载正文；持久化的是位置和按对话隔离的收藏 ID/哈希，不写入对话全文。

截图链：点击 → 防重入/取消控制 → `begin` 附加 debugger → 等待调试提示条和媒体稳定 → 滚动/几何校验 → `frame` 返回原生 PNG → 解码 Bitmap → Canvas 裁切拼接 → 编码 PNG → `end`/finally 恢复 → 写入剪贴板，失败才提供预览。分片按原始物理像素连续覆盖，PNG 编码与尺寸预算未改。

## 已完成的修改

1. **时间线**：`timeline.ts` 将全组合消息匹配换成排序后的单向遍历；用正文节点到问题索引的映射识别流式变化。同一路由未改变问题集合时复用刻度，隐藏面板不创建列表；滚动高亮只更改需要变化的属性。ResizeObserver 不再每次重绑，功能关闭会取消 RAF/定时并释放索引。刻度事件按索引读当前条目，避免不必要地捕获旧回复对象；路由切换取消长按并重新绑定。关闭面板只保留滚动数值，让悬停重开保持原位置，同时释放列表 DOM。`layout.ts` 延迟首次安装时间线。
2. **提示词**：`prompt-data.ts` 的索引按需缓存稳定排序、标签和分字段小写文本；字段边界保持原 `.some()` 搜索语义。`prompts.ts` 仅在打开时渲染、复用未变化的行，存储通知重新分配对象时也按完整字段比较复用，折叠正文按需构造；关闭库/候选时释放 DOM 和搜索缓存。候选未变化不重建，同帧输入/选区刷新合并；高亮更新前后两个选项。修订号保护初始读取，迟到的旧 get 不会覆盖较新的存储事件。没有加输入防抖延迟或引入虚拟列表。
3. **截图等待**：`moveTo` 返回刚验证的几何/修订签名，由 `capture.ts` 在没有其他异步等待的紧接续段重新读取并校验，避免滚动后再轮询同一状态。所有其他调用仍做完整稳定验证；复核前取出尚未回调的正文 MutationRecord，尺寸不变的属性变化也使签名失效。这是内部返回值调整，没有改变截图请求协议、导出模式或数据格式。没有增加常驻观察器或稳定状态缓存。
4. **撤回不安全的样式候选缓存**：本轮实际用 `stylesheet.insertRule` 让普通元素变为 fixed，候选缓存因没有 DOM 记录而漏检；最终保留每次截图时完整的计算样式检查。CSSOM、开放 Shadow DOM 新浮层、class 改变、新 sticky 和恢复已加入回归，不用局部样式读取收益换兼容性。
5. **图像内存/转换**：`base64.ts` 为截图和剪贴板共用直接字节转换；`stitcher.ts` 在 PNG Blob 编码完成后立即清零画布，再分配 base64 字符串，保存宽高后仍准确输出，减少原始像素与字符串同时驻留的阶段。`preview.ts` 在构造 Blob 后清空 base64 内容，复制重试复用 Blob。测试核对两张图只解码两次，复制/重试没有额外解码。早释放的资源时点已验证，进程峰值收益尚未量化。
6. **其他**：`dom-mutations.ts` 过滤本扩展界面插入/更新；`layout.ts` 去掉 characterData 订阅；`latex.ts` 合并隐藏定时；`mergePrompts` 为管理页/Popup 共用线性导入查重，保留原来的标签 join 等价规则。面板关闭时也释放焦点/Range 引用，避免不必要地保留旧编辑节点。`scripts/build.mjs` 在普通/测试构建压缩，watch 保留可读代码，继续 target Chrome 118。

JS 堆读数均在请求 GC 后采样，不包含 Canvas/Bitmap/GPU/系统剪贴板的原生内存。重复操作检查是短期稳定性证据，不能证明数小时运行或所有浏览器版本均无泄漏。绘图预算仍为单 Canvas 最多 1.28 亿像素（仅原始 RGBA 约 488MiB），因此**没有宣称大图原生内存峰值已下降**。没有采集 OS CPU 百分比、整个 Chrome 进程峰值或登录态站点的真实加载速度。

- 本地真实扩展截图：20 项定向回归；DPR 2/1.25 另 6 项，新版语义/标题渲染器另 2 项，原生参考逐像素差异均为 0，覆盖短/长、10456 高单张、中文/公式/富内容、嵌套滚动、吸顶/负偏移、开放 Shadow DOM、复制拒绝恢复和 125% 缩放。

- 1000 条提示词 + 时间线组合：搜索/插入、草稿保留、时间线跳转、3 次重复截图保持像素一致，且每次释放 debugger。资源采样 DOM 为 253/253/253/253，事件监听为 124/124/124/124；JS 堆为 4087292/4113376/4150988/4158496 字节。未把这段短采样当成零泄漏证明。

- `performance-regressions.mjs`：CSSOM/动态样式检查、回复检索、忙碌恢复、禁用再启用、悬停重开滚动位置、迟到的旧读取、公式隐藏计时通过；25 次截图状态创建/恢复后 DOM 和监听数量一致。即时签名可复用时无额外轮询，待处理的同尺寸 DOM 属性变更则强制完整验证。滚动对照探针复现原版 300→300、初版清理优化 300→0，已修正为只保存数值且恢复 300。窄屏检查曾在 resize 回调前读到旧布局，测试现等待同一个严格边界，未放宽越界断言。

本轮没有在用户登录态 Chrome 对话、微信/Obsidian 粘贴、系统中文输入法组合输入、Chrome 118 本体、Windows/Linux 或小时级会话上重新验收。当前 Chromium 测试不替代这些验证。未请求新权限、未引入遥测、网络上传、后台保活或图片持久化，也没有改变 Service Worker 重启后临时预览需要重建的语义。

## 2026-10-18 增量对抗审查：0.2.2 → 0.2.3

本轮由三个 agent 分别审查胶囊/提示词、截图/预览、设置/时间线，并交叉检查彼此修改。基线是本轮开始时的完整 0.2.2 工作区，不是较旧 Git HEAD；快照为 `/private/tmp/longshot-022-before-20261018.tar.gz`。保留此前未提交功能与用户数据，不访问日常 GPT 标签页。

### 已落实的增量优化

- **胶囊投影复用**：滚动时复用现有 capsule DOM；每个编辑器一次读取字体和背景；textarea 的所有胶囊共用一个镜像。先集中测量 Range，再写入胶囊位置。每帧刷新事件闭包，使悬停/双击使用当前正文和坐标，不缓存可能过期的实际几何。
- **设置队列合并**：首个保存立即启动，期间仅保留最新完整设置快照；打开提示词/时间线仍等待队列排空。拒绝一次保存不会阻塞后续更新。无关设置变化不再拆卸宽度/时间线观察器或重新全页索引。
- **预览显式释放**：清除、pagehide 或载入失败立即发送 `preview-release`，限定 exact preview URL/token、实际预览 tab ID 和顶层 frame。保留原分片重取语义，重复释放幂等；generation 阻止迟到回复复活。若关闭时消息丢失，原 tab 移除/过期清理仍兜底。

### 定向计数（本地独立 Chromium，不是登录态 ChatGPT）

| 相同工作负载 | 0.2.2 | 0.2.3 |
| --- | ---: | ---: |
| 一个 contenteditable 胶囊、20 次滚动，新建元素 | 40 | 0 |
| 同上，计算样式读取 | 80 | 60 |
| 一个 textarea 胶囊、20 次滚动，新建元素 | 60 | 0 |
| 同上，计算样式读取 | 60 | 20 |
| 500 轮对话、10 次仅 theme 改变，几何读取 | 5040 | 0 |
| 同上，全页 assistant 查询 | 20 | 0 |
| 30 次宽度 input 突发、storage/message 各模拟 30ms，保存/查询/消息次数 | 各 30 | 各 2 |
| 清除未取完的 8 个 1MiB 预览分片，后台保留 base64 字符 | 8,388,608 | 0 |

滑杆突发的首个 50 和最终 79 都保存；2 次是该受控突发场景的计数，并非任意拖动都只有 2 次。以上不宣称整个 Chrome CPU、内存峰值或截图总耗时同比下降。

### 交叉审查与保留问题

交叉审查发现“宽度变化只依赖 ResizeObserver”在截图 busy 期间可能丢掉测量，已要求显式调度几何刷新并覆盖 busy 后恢复；无关设置仍跳过重索引。胶囊 DOM 复用的当前 token/rect 闭包、undo/reorder/textarea 多胶囊，以及预览鉴权/重复释放/迟到数据都进行了独立复核。

仍有两个已复现但未在本轮扩大修改的路径：不同草稿反复替换 editor 会保留旧 State/撤销历史，30 次替换后 20 次 scroll 会产生 600 次 editor 查询；直接清掉可能损害原草稿恢复，需先设计历史迁移边界。时间线面板打开时流式更新仍全量重建可见列表，500 轮、5 次更新可创建约 17,500 个元素；下一轮适合做列表增量更新专项，不把它列为本轮已解决问题。截图完整计算样式扫描继续保留，避免 CSSOM 浮层漏检。

复现入口：`npm run test:performance`（含新增 `token-performance.mjs`、`ui-performance.mjs`），`npm run check`、`test:preview`、`test:tokens`、`test:settings`、`test:timeline`、`test:productivity` 和定向 `test:e2e`。全局性能基线为 `artifacts/performance-022-before.json`；最终版对应 `performance-023-after.json`。生产交付仍直接构建到原 `dist/`，不生成安装包，不自动操作日常标签页。登录态真实页面速度和进程峰值尚未验证。
